# 手机入口卡片越界修复

问题来自健康日记与挑战页共用的 `.service-links`。原先使用自动最小内容宽度的 `1fr 1fr`，同时依赖原生按钮的盒模型和不换行行为，存在内容把列撑宽的风险。普通桌面预览没有覆盖手机反馈的现象。

修正：

- 两列使用 `repeat(2,minmax(0,1fr))`，容器与按钮明确限制宽度、最小宽度及 `border-box`。
- 图标保留固定空间，移除重复间距；文字占用剩余空间并允许换行，卡片高度随内容增长，不裁切文字。
- 公共两列/三列网格及计划报告、营养概览、邀请、拍照额度、小队、体重页的同类网格同步使用受限列宽。
- 公共页脚按钮与带长说明的菜单项也允许收缩和换行。

验证：

- 静态检查注册页面的多列网格，不允许重新引入无最小宽度约束的等分列。
- 使用实际编译 WXML 和模拟账号数据，对除全屏媒体启动页以外的63页进行320/390宽度检查，共126组；检查整页宽度、入口按钮内部滚动宽度与图片加载。
- 健康日记和挑战页额外检查280/320/375/390/430宽度，并加入按钮盒模型与放大文字的压力场景。该模型修复前可产生越界，修复后不再越界。
- 另扫描全部63页在320宽度下的按钮内部文字，发现并修复“更多功能”页菜单长说明溢出。

这些是桌面编译预览与回归检查；手机效果需要使用最新编译生成的预览码确认。
