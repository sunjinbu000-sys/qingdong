# 扫描、营养报告与确认保存

## 页面流程

拍照/选图 → 用户确认 → 检查额度或完整观看视频 → 扫描分析视图 → 同一页的完整报告 → 核对份量 → 保存日记。

- 扫描视图显示原照片、移动扫描线、处理状态及照片草稿/分析/报告三个步骤。
- 成功报告把照片、餐次日期、标题、海报、估算热量、PFC、食材份量、分析描述、营养观察、进餐建议和次日三餐汇总在同一长页。
- 次日三餐使用横向卡片，显示食材、份量与步骤。优先读取覆盖该日期的本人轻动计划；无计划或旧计划与最新忌口冲突时，使用按当前档案过滤的模拟参考搭配，不根据单张照片计算剩余摄入量。
- 修改份量会重算食材热量、三项营养和4/4/9供能占比，不再次扣次。成功分析只建立草稿，点击保存才写入日记；重复保存不新增记录。
- 未识别结果保留原照片、食材未知、热量和营养为 null、无PFC比例；不保存为0千卡。用户可重新拍照或进入手动记餐。
- 已保存结果保留查看日记与删除入口；计划任务在保存餐食后才尝试完成。

## 真实能力与演示边界

目前没有真实识图后端。普通上传默认进入未识别结果，不能声称读取了照片或把任意图片当成鸡肉饭。拍餐页提供明确勾选的“使用餐食样例演示成功页”，用于前端验收；成功页再次说明没有分析当前照片。

样例成功分析沿用原有额度规则，幂等请求只扣一次。默认未识别演示不扣次数。样例份量范围只是界面演示的份量波动，不是模型置信区间。正式后端接入后需要返回真实食物判定、食材估量、营养及分析文本，并明确失败计费策略。

所有图片继续保存在本机；海报为本机生成与预览。相机、实际广告和海报输出仍需手机确认。当前源码总字节统计为2,031,469，实际打包大小以开发者工具为准。

## 验证

112项测试全部通过，覆盖未知值不记0、不自动入日记、草稿只扣一次、份量重算、保存幂等、本人数据隔离、原计划复用、最新忌口复查和既有拍照/视频流程。59页静态检查、原生WXML/WXSS编译及320/390宽度下三种报告状态检查通过。
