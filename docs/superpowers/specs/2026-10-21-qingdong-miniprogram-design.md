# 轻动微信小程序设计方案（已确认）

日期：2026-10-21
依据：轻动演示-V0.30.html、轻动区域健康挑战 · DDD 设计方案.pdf。

## 目标与范围
开发面向普通用户的微信小程序，以原型视觉和业务规则为参考，以 DDD 方案第一期范围约束功能。后端开发期间可以通过模拟数据完整体验，后续替换为真实接口。原型中的运营、总部、城市管理和复核后台不放入用户小程序。

第一期闭环：模拟登录 → 确认城市 → 完善健康档案 → 报名累计签到活动 → 每日签到 → 查看进度 → 领取模拟会员奖励 → 查看会员额度 → 拍照识餐模拟结果 → 查看健康日记和打卡榜。

## 技术选择
推荐沿用现有微信原生 JavaScript 工程，不增加 UI 框架和构建工具。WXML、WXSS、JavaScript 实现页面和共享组件。移除启动时对云开发环境的依赖，保留现有 cloudfunctions 示例文件但不用于业务运行。
备选：原生 TypeScript，增加类型约束但需要迁移现有模板；uni-app，适合确定需要 H5/App 的场景，但当前没有跨端需求。

## 页面与导航
底部四个入口：首页、健康日记、挑战、我的。
首页：城市、品牌问候、今日签到卡、今日健康概览、拍照识餐入口、活动推荐、打卡榜入口。
健康日记：日期选择、三餐与加餐记录、运动记录、体重记录、当日汇总；新增记录表单。
挑战：累计签到活动列表、活动详情、报名、目标与进度、规则说明、奖励状态；打卡榜详情。
我的：个人资料、城市和健康档案、会员权益与每日额度、我的奖励、隐私设置、退出模拟账号。
独立流程：首次城市确认、健康档案编辑、拍照选图、模拟识别结果、奖励列表。

## 视觉与交互
沿用原型深绿 #143f35、主绿 #1d6651、浅绿 #d4ed9c、背景 #f6f7f2、圆角卡片和温暖的鼓励文案。桌面侧栏改为移动端底部导航，宽表格改为列表卡片，不把桌面 HTML 塞入 web-view。
所有可点击入口都连接真实页面或明确的状态反馈。表单包含必要校验；列表具备加载、空数据和失败重试状态；操作中禁用重复提交。适配手机宽度和底部安全区。

## 数据与接口边界
页面只访问 services 中的业务方法；config 统一选择 mock 或真实网络模式，真实模式在接口契约确认后启用。mock 数据与业务适配集中维护，不散落在页面中。
模拟状态用 wx.setStorageSync 持久化，支持退出并重新打开后的连续体验。提供明确的模拟模式说明和重置演示数据入口。初始日期按运行当天的北京时间生成，不固定为原型演示日期。
签到按账号和北京时间日期防重；活动报名防重；进度按不同日期的有效签到计算。奖励领取在 mock 层防重并保存领取记录。模拟识餐明确说明不分析图片；相册取消不扣额度，失败不扣额度，成功结果与日记关联。
正式登录、活动资格、奖励发放、额度扣减和榜单均由未来服务端裁决，本地状态不作为生产凭证。隐私公开开关默认关闭，榜单不显示原始体重与饮食照片。

## 开发顺序与交付
1. 工程基础与首页：移除云环境启动依赖，完成全局主题、四栏导航、统一 mock 存储和首页；开发者工具编译可打开四个入口。
2. 用户与健康日记：模拟登录、城市确认、档案、按日期的饮食/运动/体重记录；重启保留记录。
3. 挑战与奖励：活动列表详情、报名、每日签到、达标进度、奖励领取、打卡榜；验证重复签到和重复领取无额外效果。
4. 识餐与会员：选图、模拟识别结果、记录归档、每日额度和会员权益；验证取消、失败和额度耗尽。
5. 联调准备与验收：统一错误处理、空态、隐私设置、清理示例入口、接口对照说明、运行说明和真机检查清单。

## 验证与验收
用 Node 内置测试验证跨日签到、防重领取、活动进度、额度、数据持久化和日期边界。检查所有页面注册、JSON、脚本语法、页面跳转和事件绑定。微信开发者工具验证 WXML/WXSS 编译、四栏切换、选图和手机安全区；真机验证微信平台相关行为。工具无法执行的平台验证须如实列为待验，不能用静态检查代替编译通过结论。

## 本轮不实现
第二期：小队、体重榜结算与复核、支付、广告、邀请奖励。
第三期：论坛、AI 长计划、商户与实物履约。
真实后端接入按可用接口分批切换，接口未就绪时保持明确标识的模拟模式。
