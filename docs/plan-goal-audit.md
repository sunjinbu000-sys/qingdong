# 计划目标换算与限制核查

## 原因

旧代码将目标速度与目标体重下限合并为一个错误。默认配置 maxWeekly = 0.5，单位为公斤/周。7 天 3 斤 = 1.5 公斤，折合每周 1.5 公斤，因此触发原有限制。该配置是产品的自动计划参考范围，不是对人体实际变化极限的预测。

## 修正

- 前台预检查和生成服务使用同一纯函数 `services/plan-goal.js`，按 1 斤 = 0.5 公斤换算。
- 周速度 = 目标斤数 × 0.5 × 7 / 周期天数。
- 把非法输入、目标体重过低、速度超范围、年龄/健康状态/记录方向等原因分别表示。
- 自动范围内继续生成。仅速度超范围时，可以调整周期，或明确确认仅记录目标；此时有效量化减重目标为 0，不执行快速减重活动，也不按该目标推导低热量摄入。
- 可延长周期 = 向上取整（目标公斤数 / 当前配置周上限 × 7）。默认配置下 3 斤对应至少 21 天；这是按产品阈值计算的周期，不是个人临床保证。
- 目标过低时必须调整，不能使用记录模式确认绕过。
- 原始目标、目标评估和有效目标随计划分别保存。输入变化不会误改已保存的历史计划。
- 实际体重记录与计划限制分离，实际较快变化仍可记录；自动计划不承诺达成。
- 预检查、失败或取消不消耗次数；确认成功生成后才按既有逻辑扣次。

## 依据与边界

- [CDC：Steps for Losing Weight](https://www.cdc.gov/healthy-weight-growth/losing-weight/)说明，一般渐进减重约每周 1–2 磅更有利于长期保持。产品不能用“有人一个月瘦30斤”的个案作为面向所有用户的自动目标。
- [NICE：Physical activity and diet](https://www.nice.org.uk/guidance/ng246/chapter/Physical-activity-and-diet)将非常低能量饮食等快速减重干预限定在具备专业支持的相应服务场景。
- 当前功能仍为本地模拟和产品规则校验，不是经临床验证的个人体重预测模型，也未接入真实 AI。既有 BMI 和年龄分流规则未被当作个体诊断。

验证：101 项测试通过；新增覆盖7天3斤换算、21天边界、30天30斤记录模式、过低目标不可绕过、非法输入、检查不扣次以及实际体重记录不受自动周速度限制。原生编译及320/390宽度显示检查通过。
